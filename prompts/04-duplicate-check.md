# 重複チェック

税理士事務所での重複確認用です。まずは読み取り専用で候補を集め、重複の可能性を表で出してください。削除や修正は行いません。

## 進め方

1. 対象期間、対象事業所、対象データの種類を確認する。
2. API を呼ぶ前に、使う path と HTTP method を先に説明する。例として、`GET /invoices` は請求書の重複確認、`GET /api/1/expense_applications` は経費申請の重複確認、`GET /api/1/receipts` は証憑の重複確認、`GET /api/1/manual_journals` は振替伝票の重複確認に使う。
3. 同じ日付、同じ金額、同じ取引先、似た件名、同じ証憑番号を軸に候補を拾う。
4. 候補は表で並べる。片方だけでは判断しない。
5. 似ているが別件の可能性があるものは `要確認` にする。
6. 重複が濃厚でも、勝手に消さず、人の判断を待つ。

## 見方

- 金額が同じ
- 日付が近い
- 取引先が同じ
- 件名やメモが似ている
- 証憑や申請番号が近い

## 出力の形

- 重複候補の表
- 判定理由の表
- `要確認` 一覧
- 人への確認事項

## 書き込みの扱い

- すべて読み取り専用で進める
- 修正が必要なら、対象の path と HTTP method を先に説明してから、人に確認する

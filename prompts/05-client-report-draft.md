# 顧客向けレポート草案

税理士事務所がクライアントへ渡す月次レポートの草案作成用です。まずは読み取り専用で材料を集め、表を先に作ってから文章にします。書き込みはしません。

## 進め方

1. 対象の事業所、対象月、レポートの相手先、欲しい観点を確認する。
2. API を呼ぶ前に、使う path と HTTP method を先に説明する。例として、`GET /api/1/reports/trial_pl` は損益の要約、`GET /api/1/reports/trial_bs` は残高の要約、`GET /api/1/expense_applications` は経費の動き、`GET /invoices` は請求の動き、`GET /api/1/receipts` は証憑の動きの確認に使う。
3. まず数字を集め、次に気になる変化だけ補足する。
4. 文章より先に、表で事実を固める。レポート本文はその後に短くまとめる。
5. 説明が足りない部分、読み取り切れない部分、他資料と合わない部分は `要確認` にする。
6. 外へ出す文面に直す前に、内容確認のための人チェックを挟む。

## 出力の形

- 月次の要点表
- 変化が大きい項目の表
- `要確認` 一覧
- レポート草案本文

## 書きぶり

- 断定しすぎない
- 専門用語は必要最小限にする
- 事実、推定、確認待ちを分けて書く

## 書き込みの扱い

- 使うのは読み取り専用の API のみ
- 何かを保存・登録・修正する必要が出たら、先に path と HTTP method を説明して人に確認する

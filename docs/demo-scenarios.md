# デモシナリオ

この文書は、税理士事務所や経理担当者に見せるデモの進め方をまとめたものです。
デモは「使えること」よりも「安全に使えること」を見せる目的で行います。

## デモ1: 接続確認

### 目的

Codex Desktop から freee-mcp に安全に接続できることを示す。

### 前提

- 認証が完了している
- デモ用または確認用の事業所を使う
- 実データの変更は行わない

### 手順

1. 認証状態を確認する
2. 事業所一覧を取得する
3. 現在の事業所を確認する
4. ユーザー情報を確認する

### 期待結果

- 接続状態が分かる
- どの事業所を見ているかが分かる
- 読み取りだけで確認が終わる

### 人による確認点

- 事業所が正しいか
- ユーザー情報が想定通りか
- 認証情報を画面に出していないか

## デモ2: 月次チェック

### 目的

今月と前月の差分を見て、確認すべき項目を絞れることを示す。

### 前提

- 今月と前月の対象期間を決めておく
- 読み取り専用で進める
- 実行や更新はしない

### 手順

1. 今月の取引一覧を取得する
2. 前月の取引一覧を取得する
3. 重複候補を探す
4. 金額が大きい取引を抽出する
5. 要確認リストをまとめる

### 期待結果

- 月次の差分が見やすい
- 重複や異常値が分かる
- 人が見るべき点に絞れる

### 人による確認点

- 比較対象の期間が正しいか
- 要確認リストが過不足ないか
- 断定してはいけない項目が混ざっていないか

## デモ3: 請求書ドラフト

### 目的

過去データを参考に、請求書の下書きだけを作れることを示す。

### 前提

- 先月の請求書を確認できる
- まだ登録はしない
- 実行前に人の承認を取る

### 手順

1. 先月の請求書を取得する
2. 今月分の請求書案を作る
3. 登録前確認表を作る
4. 人が承認した場合のみ登録する

### 期待結果

- 下書きが表で見える
- 取引先、品目、税区分、金額、備考が確認できる
- 登録前に止められる

### 人による確認点

- 金額と税区分が正しいか
- 送付先と宛名が正しいか
- 登録してよいか

## デモ4: 経費確認

### 目的

経費申請や支出取引の確認を、読み取りと候補整理だけで進められることを示す。

### 前提

- 経費関連の確認対象を決めておく
- 類似取引を参照する
- 登録や修正はしない

### 手順

1. 経費関連取引を取得する
2. 類似取引を確認する
3. 勘定科目候補を整理する
4. 税区分候補を整理する
5. 部門候補を整理する
6. 要確認項目を出す

### 期待結果

- 参考にする取引が見える
- 候補が表で整理される
- 判断が必要な点だけ残る

### 人による確認点

- 勘定科目候補は適切か
- 税区分候補は妥当か
- 部門や金額がずれていないか

## デモ5: 顧問先向け報告文

### 目的

freee から取得した情報だけを材料に、月次報告文の下書きを作れることを示す。

### 前提

- 数値は取得結果の範囲に限定する
- 推測で断定しない
- 専門用語は減らす

### 手順

1. 月次の確認結果を集める
2. 報告文の下書きを作る
3. 要確認事項を明記する
4. 人が文章を見直す

### 期待結果

- 顧問先向けの文面が短時間で整う
- 要確認事項が分かる
- 事実と推測が混ざらない

### 人による確認点

- 数値が freee の取得結果と一致するか
- 言い回しが分かりやすいか
- 断定しすぎていないか

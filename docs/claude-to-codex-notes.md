# Claude Code から Codex へ移るときのメモ

このメモは、Claude Code のプラグイン運用に慣れている人が、Codex Desktop で同じリポジトリを使うときの違いを整理したものです。

## いちばん大きな違い

Claude Code では、プラグインを入れると、MCP サーバーと関連するスキルをまとめて扱いやすくなります。
一方で Codex では、Codex Desktop 側に MCP サーバーを登録して使うのが基本です。

つまり、Claude Code は「プラグインを入れて使う」感覚が強く、Codex は「MCP 接続を自分で組む」感覚が強いです。

## Claude Code のとき

- Marketplace からプラグインを追加する
- プラグインの中で MCP と関連資料をまとめて使う
- Claude Code の画面やコマンドから導入する
- プラグイン単位で運用をそろえやすい

## Codex のとき

- Codex Desktop に MCP サーバーを登録する
- このリポジトリの README や docs を見ながら使う
- 必要ならローカルの `bun run dev` でサーバーを立てる
- 読み取り専用から始め、書き込みは人間確認を挟む

## 実務上の見え方

Claude Code から来た人は、最初に次の違いを意識すると迷いにくいです。

- プラグイン前提か、MCP 登録前提か
- どこで設定するかが違うか
- どの画面で確認するかが違うか
- どこまでを自動化してよいかが違うか

## 置き換えるときの注意

- Claude Code 用のプラグイン手順を、そのまま Codex に持ち込まない
- Codex では、MCP 設定の例を参考にして接続する
- どちらでも、登録、更新、削除は人間確認を必須にする
- 税務判断はどちらの環境でも人間が責任を持つ

## 使い分けの考え方

- すでに Claude Code の運用があるなら、同じ業務ルールを Codex にも持ち込む
- Codex では、まず読み取り系の確認だけで動きを掴む
- 書き込み系は、どのツールでも同じく慎重に扱う
